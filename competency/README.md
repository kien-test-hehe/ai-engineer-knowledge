# Middle AI Engineer — Competency & Evidence

**Primary track:** AI Application / LLM Engineer. Middle is **independent engineering ownership in a defined scope**, not necessarily advanced knowledge of every topic in the 37-module catalog.

## Five competency pillars

| Pillar | Middle-level evidence |
|---|---|
| Model understanding | Explain ML/DL/Transformer, training, inference and failures; debug shape/gradient/numerical issues |
| AI application | Build a secure, tested LLM service, evaluated RAG and a recoverable tool workflow |
| Fine-tuning & performance | Choose RAG vs SFT/LoRA, train/fine-tune when justified, benchmark inference, memory and quality |
| Production reliability | Docker/CI, authentication, logging, tracing, monitoring, rollbacks and incident analysis |
| Engineering judgment | Architecture, baselines, cost/latency/quality trade-offs, code review and technical documentation |

**Practical gate:** demonstrate the [integrated capstone](../curriculum/LEARNING_PATH_V2.md#phase-11--system-design-capstone--engineering-ownership-core-610-weeks) with explicit acceptance tests, working artifacts and a design review. Review quality, independent contribution and collaboration; completing this roadmap alone is not a job-title certification.
